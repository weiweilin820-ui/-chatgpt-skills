# 随机写真融合版 V2

V2 的目标不是堆更多关键词，而是让人物身份、摄影企划、动作、美姿、镜头、光线和成像系统彼此一致。

## 核心优先级
用户明确指定 > 安全与成年限定 > Strong Identity Lock > 参考图职责 > 场景/故事瞬间 > 人物美姿 > 摄影机决策 > 光线物理 > 成像系统 > 风格修饰 > 负面约束。

## 1. Strong Identity Lock

### 有人物参考图：默认自动开启
把人物参考图视为唯一面部身份来源。这是“同一个人物换场景拍摄”，不是根据参考图重新设计一个相似人物。

必须保持参考人物可识别的整体脸部身份，包括脸型比例、眉眼关系、眼睛形态与间距、鼻部比例、嘴唇轮廓、下颌线、面部软组织比例以及与参考图一致的整体年龄感。不要用长串新五官描述与参考图竞争，也不要自行美化成另一张脸。

摄影风格、妆容、灯光、焦段、服装、Editorial/电影化审美不得重新塑造人物面部。禁止因为“高级感”自动成熟化、网红化、模特化、明星化或改变原人物脸型比例。

内部优先级固定为：Identity fidelity > face visibility > pose > lighting > cinematic styling。

允许变化：发型、发色、妆容强度、服装、饰品、姿态、表情、场景、镜头、光线和摄影风格，除非用户锁定其中某项；这些变化都不得牺牲人物身份。

### 身份保护镜头规则
首次换场景测试、或上一张已经出现身份漂移时，自动进入“身份保护模式”：
- 优先正面至轻微三分之一角度，脸部转动约 0–15°。
- 双眼、鼻口和下颌主要结构尽量完整可见。
- 避免一开始就使用大侧脸、背身大回头、严重俯仰、头发遮半脸、强逆光、脸部深阴影、运动模糊。
- 全身/远景增加高信号要求：人物脸部仍清晰可辨，保留参考人物身份特征。
- 85mm/电影光/Editorial 只能改变摄影表现，不能改变人物脸。

当身份已稳定，且用户明确需要更大角度时，才逐步放宽到更明显三分之一侧脸或回头动作。

### 强身份 Prompt 前缀
有参考人物时，最终 Prompt 前部应压缩表达以下含义：严格以参考图作为唯一人物身份源；保持同一人物、同一脸部身份与比例；这是同一个人换场景拍摄；摄影风格、妆容、灯光、焦段和服装不得重新设计面部；身份一致性高于姿势和风格。

不要机械重复十遍“same face”，保持高信号、低噪音。

### 无参考图
才启用文字人物锚点。默认人物可读取 V1 `../随机写真融合版/references/人物层.md`；用户提供人物设定时优先使用用户设定。

## 2. Reference Roles
存在多张参考图时，内部给每张图分配职责：Identity、Outfit、Pose、Composition、Lighting、Environment、Style。同一张图可承担多个职责，但不得把不同人物参考图的身份特征混合到一个人脸上。用户说“只参考衣服/姿势/场景”时，不把该图当身份源。

## 3. Story Moment
优先生成正在发生的瞬间，而不是标准摆拍。动作必须有清楚身体骨架，避免互相冲突。若用户没有指定姿势，按需读取 `references/人物美姿导演.md`。

当 Strong Identity Lock 处于身份保护模式时，美姿导演不得为了“抓拍感”强制大幅回头或遮脸；先保身份，再增加动作戏剧性。

## 4. Camera Director
24–28mm：强环境、近距离广角、低机位、旅行抓拍。
35mm：生活纪实、街头、空间关系。
50mm：自然人眼感、中近景。
85–135mm：人物突出、背景压缩、安静观察。
135–200mm：远距离观察与空间压缩。
机位与焦段必须匹配。身份保护模式下，镜头选择不能以牺牲脸部可读性为代价。

## 5. Composition
每组只选一个主构图逻辑：中心稳定、偏心留白、前景遮挡、框中框、极低机位仰拍、高机位俯拍、镜面/玻璃反射、人物小比例大环境、近景侵入、动态裁切。前景遮挡不得遮住身份关键面部区域。

## 6. Lighting Physics
按“来源 → 方向 → 落点 → 结果”组织。只能有一个主光逻辑。身份保护模式下必须让脸部获得足够信息量，不能为了低调电影感把身份关键结构压进死黑。

## 7. Imaging System
每张图只选一个主成像系统：真实手机原相机、CCD/direct flash、35mm film、Pro-Mist柔雾、中长焦高清人像、低调电影摄影。成像系统服务人物，不得反向重塑身份。

## 8. Conflict Resolver
生成前内部检查：人物身份是否被风格重新设计；姿势是否导致脸部信息损失；焦段与机位是否冲突；主光是否超过一个；成像系统是否打架；服装与场景是否协调；构图是否矛盾。若冲突，Strong Identity Lock 优先删除低优先级修饰。

若用户反馈“不像参考人物/脸偏了/换人了”，下一次自动：提高身份约束、降低脸部转角、减少遮挡、保证双眼鼻口可见、降低会重塑脸的风格化描述；不要只重复原 Prompt。

## 9. Targeted Negative
负面词只针对当前问题。有人物参考图时优先加入身份漂移、不同人物、重新设计面部、脸型改变、五官比例改变、过度成熟化、网红脸/模板脸、塑料皮肤、过度磨皮；再按任务加入人体/手部错误、穿模、错误文字、水印等。

## 10. 人物美姿导演
未指定 Pose 或要求自然抓拍时读取 `references/人物美姿导演.md`；要求多组随机美姿/动作去重时再读取 `references/美姿变量池.md`。

美姿结构：动作动机 → 重心 → 躯干 → 肩胯 → 腿部 → 主动作手 → 辅助手 → 头部 → 视线 → 表情 → 环境互动 → 抓拍时刻。

原则：一张图一个主要动作；手优先合理互动；优先动作中间帧；全身明确承重和脚位；多组至少改变重心、主动作、视线、身体朝向、手部任务中的三项。身份保护模式覆盖任何可能导致脸部大幅偏转/遮挡的随机美姿。

## 12. 按需加载
默认不要一次读取所有 references。有参考人物即执行 Strong Identity Lock；未指定姿势/自然抓拍才读人物美姿导演；多组随机动作才读美姿变量池；明确远距离观察感才读偷拍感模式；随机服装/场景才读对应变量池；特殊成像才读摄影语言与成像机制。用户锁定大量条件时不额外随机无关变量。

## 13. 批量差异
n>1 时至少让场景、故事瞬间/美姿、焦段/机位、主成像系统四项中的三项明显变化；身份保持不变。使用美姿变量池时相邻两组避免重复同一手部任务、重心与视线。

## 14. 输出
默认每组输出：简短标题/要素卡 + 中文完整 Prompt + 英文完整 Prompt + 精准负面词。Prompt 使用连贯自然语言，不堆关键词。有人物参考图时，身份约束必须位于完整 Prompt 前部，而不是埋在末尾。

## 15. 身份漂移修复示例
用户说“人像和参考偏了”时，不需要重新随机全部企划。保持用户认可的场景/服装/光线，只修正身份相关变量：开启身份保护模式，将大回头改为轻微转头，确保脸部主要结构可见，并在 Prompt 前部强化唯一身份源与同一人物约束。
