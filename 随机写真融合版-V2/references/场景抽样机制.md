# 场景抽样机制

## 三级随机

综合随机时，依次抽取 **场景领域 → 空间原型 → 具体地点**，最后再抽可发生的活动。先从下列 **12 个等概率领域** 抽一个，再在该领域内选择空间原型及 `场景名词池.md` 的具体地点。用户指定主题时只在主题相容领域内抽。不要按表格顺序轮换或人为保证每类都出现；100 次独立抽取可以出现领域数量波动。同一具体地点在同批次只出现一次。

| 领域 | 关联场景章节 |
| --- | --- |
| 住居和微型日常 | 1、5、6、45、46 |
| 街区和公共服务 | 2、3、4、7、19 |
| 手作和艺术 | 8、9、15、20 |
| 运动与玩乐 | 31、32、33、34 |
| 中国自然与户外 | 11、12、13、35、38、39、44 |
| 中国古迹和地域生活 | 14、36、40 |
| 海外旅行 | 37、41、42、43 |
| 工业、科技和未来 | 10、17 |
| 东方神话与幽冥 | 24、25、26、30 |
| 西方奇幻与异族 | 18、27、28、29、30 |
| 末世、灾变与生存 | 21、22、23 |
| 特殊地貌与设施 | 13、16、19、20、本页扩充项 |

章节重叠有意存在：先抽领域，再抽空间原型、内部章节和地点，避免某个章节因为条目多而压倒其他领域。对全部 100 组，先用实际随机数生成场景领域、空间原型、具体地点和画幅的候选列表，再撰写提示词；不要边写边沿用上一个场景的联想。可以用 `python3` 的 `secrets.SystemRandom().choice` / `.choices` 实现；若环境不能运行代码，用显式编号随机抽取，也不要称未执行的过程为“真随机”。

## 空间原型池

空间原型描述画面的几何关系，不等同于地点名称。酒店走廊、宫殿回廊和会展连廊即使属于不同题材，也都算“纵深通道”；咖啡馆窗边、列车窗边和飞船舷窗旁都算“临窗停留”。从下列原型中选择与领域相容的一项：

1. 开阔水岸或湖面
2. 山径、林道或花田路径
3. 广场、庭院或露天市集
4. 球场、跑道或训练区
5. 工坊、画室或后台工作台
6. 商店、摊位或服务窗口
7. 卧室、客厅或微型生活角
8. 镜墙、梳妆镜或街角反射面
9. 纵深走廊、回廊或隧道
10. 楼梯、桥梁、栈道或悬空索道
11. 站台、候乘区或交通舱室
12. 车内、船舱或移动载具旁
13. 高台、屋顶或观景平台
14. 遗迹、废墟或灾后临时设施
15. 宫殿、仪式厅或神话殿堂
16. 洞穴、地下城或特殊地貌内部
17. 展厅、剧场或大型活动空间
18. 临窗座位、舷窗或玻璃幕墙边

空间原型不是固定轮换表，而是去重用的第二层标签。批量抽取时，对最近 8 张中已出现两次的原型临时降权；连续两张不得采用相同原型。10 张以上的批次原则上不少于 7 种空间原型，除非用户指定的单一主题确实限制空间类型。不要仅靠把“走廊”改名为“回廊”“通道”来通过检查。

## 新鲜度检查

在生成前，从用户可见的最近几批导演卡提取“场景领域 + 空间原型 + 具体地点 + 主设施 + 主要事件”记录；只用实际可见记录，不假装拥有完整历史。对新抽样：

1. 同批次：拒绝重复地点，或只换衣服但空间骨架、设施与动作都相同的卡。
2. 对最近一至两批可见卡：优先拒绝同一具体地点、同一地标的相同取景点、同一空间原型下相同主设施与事件组合；允许同类但几何关系和活动真正不同的小空间。
3. 若一半以上候选又落入老套的酒店走廊、便利店、咖啡馆、地标前静站等模式，扩大到本页未用的小空间重新抽取；保留随机抽样结果中的不寻常场所，不将其编辑回熟悉背景。
4. 只修复重复、安全和空间逻辑问题，不为了“平均分布”而重新洗成轮流出现的固定题材顺序。
5. 相邻两张至少在“领域、空间原型、活动、主设施、时段/天气”中改变三项；仅更换城市名、朝代名、灯光颜色或背景装饰不算新场景。

## 动作中的镜头回应

直视镜头与正在做事可以同时成立：从手头事务中短暂抬眼，手保持在画笔、船票、工具、球拍、手机或花束上，动作停在合理的中途帧。例如画室里一手扶画板一手握笔看镜头、码头递票时抬眼、工作台分拣信件时朝拍摄者笑。约八成卡片使用清晰的直接眼神接触，其余保持面部可见；不看镜头的卡片尽量不连续出现，只有动作安全或叙事确实需要时才保留。“直视”不等于静站合影。只有驾驶、攀岩、危险工具操作等需要持续注意力的动作，安排安全停顿后再看镜头。

## 从零整批抽样与语义去重

“从零开始”指重新建立候选组合，不读取旧卡片作为改写母版。固定人物前缀、身材锚点和负面提示词不计入相似度；比较的是场景、空间、动作、服装轮廓、材质、成片机制和摄影选择。

批次达到 5 组时，先建立不少于 `max(4N, N+60)` 条候选计划，再运行 `scripts/select_batch.py`。候选计划必须包含：

`scene_domain｜spatial_archetype｜venue｜facility｜activity｜pose_family｜outfit_family｜top_silhouette｜bottom_silhouette｜material｜artistic_finish`

候选池的构建规则：

1. 场景四元组 `领域＋空间原型＋具体地点＋主要设施` 独立抽取并做物理校验，不能用更换城市名伪装成新空间。
2. 动作记录“动作目的＋姿态家族＋主要互动物”，把“站立、靠墙、叉腰”等静态外形与真正的活动语义分开；综合随机批次中，纯站姿不得成为多数。
3. 服装记录“家族＋上身轮廓＋下身/一体式轮廓＋主材质”，换颜色、丝袜、鞋或配饰不算新服装。
4. 艺术成片记录实际成像机制；仅修改效果名称而光影机制相同，仍视为近重复。
5. 若旧批次在当前对话中可见，把其具体地点、地点—动作组合和服装轮廓指纹作为冷却项；不要复制其整句再替换名词。

选择后的最低审计：

- 具体地点与完整服装指纹均应达到 `N/N` 唯一。
- 相邻两卡在九字段组合指纹中至少改变四项。
- 50 组不限定主题的综合随机批次，目标不少于 10 个场景领域、14 种空间原型、35 种动作语义、30 组服装轮廓配对；候选池受用户主题限制时按实际可用范围缩减。
- 综合随机批次至少覆盖坐姿、蹲跪、行走动态、伸展/倚靠和站姿中的四类；站姿原则上不超过 25%，其中“静态站姿＋全身”控制在约 10% 以内。全身优先留给行走、运动、明确动作或确需展示鞋履/完整造型的场景。
- 约 80% 为动作中直视镜头；不看镜头约 20% 或更低，并避免连续出现。这不是单列的表情或视线模块。
- 画幅按摄影语言池权重抽取，横幅保持低占比；16:9 不得使用全身或远景。
- 丝袜只在服装、动作、天气、鞋履和景别均相容时加入；黑色基础款不超过丝袜卡约 35%，紫灰或薰衣草紫丝袜只作低频点缀。

脚本的审计不替代人工兼容性检查。脚本通过后，仍需逐卡检查服装协调、场地安全、鞋履、前景遮挡、脸部占比和成片光学逻辑。
